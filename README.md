# ChatBridge Signal 自定义客户端 · Windows 构建工程

本工程以 Signal Desktop 官方稳定版 v8.33.0 为基础，保留其独立扫码、手机历史转移、加密数据库和媒体恢复流程，加入翻译界面以及应用内 WhatsApp 多账号工作区。它不搬入现有 Signal 桌面窗口，也不使用用户原来的 Signal 数据目录。

**这是待构建的源码工程，不是安装包。Windows 构建、真实扫码关联、手机聊天记录和最近 45 天媒体转移尚未验收；不能当作已经支持这些功能的成品使用。**

## 已经准备的内容

- `prepare_source.py` 从官方仓库取得固定版本，并校验完整提交 SHA。遇到版本或源码状态不符会停止，不自动对其他版本打补丁。
- 新客户端使用 `%APPDATA%\ChatBridgeSignal`，首次运行按官方关联流程显示新设备二维码。既有 `%APPDATA%\Signal` 不读取、不复制、不删除。
- 官方 `AccountManager` 和备份导入核心源码保持逐字节一致；手机是否转移历史，沿用原有授权选项。真正支持程度要经过下面的实机验收，保留代码不是实测成功的替代证据。
- 翻译扩展会自动翻译当前聊天已加载及新收到的文字消息，保留原文并将译文显示在下方；已移除历史/新消息开关，仅失败时提供重试按钮；翻译采用随安装包提供的 CPU 本地中英文模型，无需 Azure 密钥，也不发送翻译文本到云端。首次翻译需要加载模型，速度受电脑性能影响。
- WhatsApp 使用同一个客户端的内嵌 WebContentsView，各账号独立会话目录。首次运行需要重新扫码，不能直接沿用旧 Qt 版本登录缓存。
- Windows 构建工作流生成未签名的 `ChatBridge.exe` 和完整依赖目录，并上传对应源码补丁。

## 已有验证

扩展测试覆盖自动翻译已加载和新增消息、切换聊天、切换译文语言、失败后重试、批量处理与缓存，以及多账号隔离、更新校验和渲染进程权限。

源码准备脚本已在独立干净工作树中执行通过。已核对固定提交中官方关联和历史导入文件保持原样。补丁后的主进程及 preload TypeScript 做过语法转换检查。

没有做过完整上游依赖安装、完整 TypeScript 类型检查、Electron 实际启动或 Windows 打包。这些是工作流要执行的后续步骤，构建失败时需要根据日志继续修正。测试使用模拟 DOM，不能证明真实聊天页面选择器始终有效。

## 运行 Windows 构建

将本工程放入一个允许使用 GitHub Actions 的仓库后，上传到 `main` 分支后会启动构建；也可在 Actions 手动运行 `Build ChatBridge Signal on Windows`。

流程使用 Windows runner：取得已固定的官方源码、配置与源码一致的 Node/pnpm、安装依赖、生成资源、检查 TypeScript、打包 Windows x64 程序。不会自动发布到任何 release，不使用签名密钥，不上传手机二维码、聊天数据或翻译密钥。产物名带有 `unverified`，直到完成实机验证。

打包完成后，必须使用整个 `win-unpacked` 目录，不是只复制其中的 EXE。当前工作流先产出可运行目录；传统安装器、签名和自动更新服务器还未完成。

## 必须通过的实机验收

1. 新客户端显示新设备二维码，电脑原有 Signal 仍保留原登录和数据。
2. 用户用自己的手机 Signal“关联设备”扫码；在手机选择“转移聊天记录”。
3. 等待原生历史转移完成，核对几个旧聊天的文字、时间和联系人。
4. 检查最近 45 天内具有代表性的图片、视频、语音能打开；记录失败、过期、缺失或尚未下载的项目。不能只凭显示“同步完成”判断媒体完整。
5. 检查新消息收发、阅后即焚、删除、群聊及翻译按钮行为。
6. 打开聊天即自动翻译已加载文字；收到消息或滚动加载旧消息时自动追加译文，不需要开启任何开关。
7. 重启后会话和媒体仍可使用；WhatsApp 账号间登录状态隔离。

二维码关联和历史转移完成需要用户手机参与，构建工程无法替用户确认或证明这一步成功。不要将二维码、关联密钥或整个数据目录发给他人。

## 当前限制

- 这是一项非官方自定义构建，不是 Signal 官方发布版本。原生协议和历史转移代码来自所固定的上游版本。
- Signal 支持独立进程、独立窗口的多账号管理，各账号独立扫码、数据库和实例锁。默认账号沿用已有数据目录；其他账号使用独立目录。顶部可添加或打开账号。WhatsApp 工作区支持多个会话。多账号真实手机扫码及同步仍待 Windows 实测。
- 翻译只处理已加载的文字，媒体恢复由上游客户端负责，不对图片/语音内容做翻译。
- 原生发消息界面沿用上游客户端。本工程未加入中文草稿的英文预览功能，旧 Qt 原型的该功能不能当作本工程已有功能。
- 官方 Signal 自动更新在本工程中禁用，避免被官方包覆盖自定义界面。本工程自己的更新源和签名安装更新尚未接通；不能承诺自动更新。
- 必须持续跟进上游版本和协议变化。此工程固定提交用于可重复构建，不意味着可永久使用同一个底层版本。

### 更新缓存清理
应用启动时仅清理带 ChatBridge 专用标记的更新缓存：目标构建号已经安装的包立即尝试删除，未成功安装的残留包在七天后重试清理；下载或校验失败立即尝试删除临时文件。被 Windows 锁定的文件保留到下次启动重试。不会扫描聊天数据库、浏览器会话、用户下载目录或手动解压的旧版文件夹。安装到同一路径时由 NSIS 替换程序文件；安装到不同路径仍可能保留旧版。


## Fixed-workspace 实验分支
此分支将 ChatBridge 主界面与 Signal 原生内容分离，使用 Windows 原生父子窗口关系把程序自行启动的 Signal 实例固定到同一主窗口工作区。没有导入用户已有的 Signal 窗口。每个账号仍有独立进程和数据目录，应用内不提供拖动或弹出操作。WhatsApp 使用主窗口中的独立 WebContentsView。新原生窗口接入需要 Windows 验证；分支构建不发布到公开自动更新渠道，先执行本地空白窗口的原生嵌入测试，再提供手动测试安装包。真实扫码、历史和媒体转移尚待实测。

## 本地离线翻译

模型：OPUS-MT / Argos en-zh、zh-en 1.9，构建时按 SHA256 校验，随安装包分发；不在运行时下载。CTranslate2 CPU int8 推理，无需 Python 安装。每次最多 10000 字符，长消息分段翻译。网址、邮箱和常见表情保留原文。仅支持中英文互译；无云端额度，但速度受硬件影响。模型来源、CC-BY-4.0 许可与作者信息在 resources/local-models 中。

## 本地翻译提速

启动后预热英译中模型；中英模型按需加载并保留在内存中，避免往返切换时反复加载。使用 CPU int8（硬件支持时）和快速单束解码，历史消息与新消息都经过批量推理。单批最多 8 条并限制总长度，避免无界并发。重复请求合并，已完成译文在内存中缓存（最多 512 条、约 200 万字符），退出后清空，不写聊天文本到日志或缓存文件。WhatsApp 页面变化触发消息扫描，并保留轮询回退。提速取决于硬件与消息长度，首次安装后的模型加载仍需要时间。

## 自动翻译界面

已移除历史翻译和新消息翻译开关。聊天打开、消息新增、历史文字加载、译文语言改变时自动翻译。成功译文显示在原文下方；原语言与译文一致时不重复显示。失败只显示重试入口，不反复自动重试。切换聊天会丢弃尚未开始的旧请求。

## 可调侧栏

账号栏默认宽度 144px。拖动右侧分隔线可在 88–320px 之间调整，松开后保存。窄栏隐藏账号文字，名称仍可通过悬停查看。双击分隔线恢复默认宽度；键盘方向键也可调整。WhatsApp WebContentsView 和 Signal 原生嵌入区域同时重排。

## 聊天内容缩放

WhatsApp 和 Signal 聊天工具栏增加“− / 百分比 / ＋”。范围 50%–200%，点击百分比恢复 100%。支持 Ctrl+加减号、Ctrl+0 和 Ctrl+鼠标滚轮。缩放使用 Electron 独立页面缩放，不改变外层账号栏与主页布局；每个账号的比例单独保存在本地设置中，重新打开时恢复。
