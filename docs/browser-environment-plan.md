# ChatBridge 浏览器环境：架构核查与分阶段实施

状态：已接入浏览器环境管理器、WhatsApp 与自定义网站适配器、标签操作、配置和实际检测。Windows 验收见对应构建任务。
核查基线：`614dec8fb0787c17073ea076fe295fc6fbde1f25`。

## 最终范围

当前实现对象为 WhatsApp 和自定义 HTTP/HTTPS 网站。浏览器环境、网站账号会话、标签页是三个独立对象。Signal 保留原有运行方式，不注册环境适配器，不读取浏览器环境配置。

同一环境下的网站账号会话继承同一份代理和浏览器环境配置，但拥有不同的持久化会话分区。同一账号的多个标签页引用同一个账号会话；同一网站的第二个账号必须创建新会话，不能靠多开标签页隔离。

## 已核实的现有架构

| 位置 | 当前实现 | 本轮改造边界 |
| --- | --- | --- |
| `extension/main.cjs` | WhatsApp 账号记录、WebContentsView 创建、代理连接、缩放、翻译授权、未读通知混合在主程序中；视图以账号 ID 为键 | 逐步抽出 WhatsApp 适配器和浏览器环境管理器；共享主程序仅保留路由和布局集成 |
| `extension/proxy.cjs` | 会话级代理，Windows 保护的认证信息，出口 IP/时区检测，失败暂停网络 | 作为可按软件调用的会话服务保留；不为 Signal 注册控制器；从环境配置提供代理参数 |
| WhatsApp session partition | `persist:chatbridge-wa-<account-id>`，现有 Cookie、缓存和站点存储已隔离 | 原分区名原样复用，不清除、不复制 Cookie 数据库 |
| `extension/preload.cjs` | 共用预加载文件中通过 WhatsApp/Signal 标志分流；包含宿主和 WhatsApp 功能桥 | 新自定义网站不使用这个特权预加载；后续修改限定宿主/WhatsApp 分支并回归 Signal 分支 |
| `extension/host.cjs` | Signal 的命名管道、认证、多进程、原生窗口嵌入和焦点管理 | 冻结现有文件，不接入环境管理器 |
| `extension/native-window.ps1` | Signal 的 Windows 窗口控制 | 冻结现有文件 |
| `prepare_source.py` | 固定 Signal 上游版本，保留历史/媒体协议，设置现有 Signal 数据路径 | 冻结现有文件；浏览器管理开发不改这些补丁 |

当前 WhatsApp 与 Signal 使用同一发行包的 Electron 版本。现有独立 session 不等于独立的内核版本，也不是 AdsPower 定制内核。新模块禁止通过全局命令行开关修改 Signal 的 UA、语言、时区、渲染或网络行为。

当前已有能力：账号分区、独立代理、出口时区、密码加密、断线限制、自动翻译、图片复制、未读徽标、账号排序和缩放。
当前缺少能力：环境级实体、多标签视图管理、网站账号绑定、环境指纹配置文件、语言/位置联动、配置与实际环境检测。

## 最小数据模型

### Environment

保存稳定 UUID、名称、schemaVersion、revision、代理配置、指纹配置、账号会话列表、标签页列表、活动标签页、排序、创建/更新时间、迁移版本。配置原子写入，并保留可恢复的上一版。

代理密码继续使用 Windows 保护机制，不能进入诊断、概览、源码或导出模板。一个环境的代理/指纹配置是唯一权威来源；账号会话引用它，不维护会发生漂移的独立副本。

### SiteAccount

保存稳定 UUID、environmentId、adapterId、平台显示名称、账号名称、备注、持久化分区 ID。显示名称不能决定适配器权限。WhatsApp 适配器按官方 HTTPS 域名验证 URL。

新账号使用全新分区。旧 WhatsApp 账号记录其已有分区，并保持该引用不变。不能把浏览器环境目录或分区当作 Signal 数据目录。

### Tab

保存稳定 UUID、environmentId、siteAccountId、URL、排列位置和显示标题。刷新和拖动不重建账号会话。重启从保存的引用恢复，不生成替代 UUID。

- 新增网站：选择现有账号会话，或创建新账号会话。
- 新增账号：创建新的持久化分区，即使 URL 与已有账号相同。
- 复制标签页：复制当前 URL，并引用原账号会话；明确提示它不是新账号。
- 关闭标签页：释放该视图，保留账号登录数据。
- 拖动：当前环境内部调整顺序。跨环境移动不在本期范围，防止误带会话。
- 关闭最后一页：显示该环境的空白主页，不删除环境或登录数据。
- 恢复：按持久化顺序恢复，先应用代理/环境配置，再加载外部网站。

## 存储和隔离

新环境配置建议存放在 `appData/ChatBridgeBrowserEnvironments/<environmentId>/`，新账号会话使用该浏览器命名空间下的独立存储路径。不得通过修改全局 `app.setPath(userData)` 来切换浏览器环境。

现有 WhatsApp 的分区目前位于发行包的 Electron userData 命名空间内，属于 session 级隔离；不能把它描述成已经拥有完全独立的产品数据根。旧 WhatsApp 会话保持原址和不可变分区映射，正常 Cookie 写入继续工作；不在运行时搬迁数据库。新的环境配置与新建会话从独立的浏览器命名空间开始保存。

不同环境：不共享分区、代理控制器、配置对象或缓存。
同一环境内的不同账号：共享环境配置值，但不共享持久化账号分区。
网站账号会话中的跨域导航：遵守浏览器原有的 Cookie 域及 LocalStorage 源隔离，绝不人工复制 Cookie、登录令牌或 Authorization 到另一个源。同站点域 Cookie 的正常浏览器语义不应被描述成绝对按 URL 隔离。

Signal 的 `ChatBridgeSignal`、`ChatBridgeSignalProfiles`、`ChatBridgeSignalAccounts` 保持现状。不得把 Signal 数据迁到环境目录。

## 模块边界

只引入当前需要的模块，不增加第三方平台占位实现：

1. 环境配置仓库：校验、原子保存、版本迁移、恢复；不引用 Electron 或 Signal。
2. 浏览器环境管理器：Environment → SiteAccount → Tab 生命周期、布局和恢复；通过适配器调用平台功能。
3. WhatsApp 适配器：官方 URL、现有登录分区、翻译、图片菜单、未读数、账号会话兼容层。
4. 通用网站适配器：HTTP/HTTPS URL、沙箱视图、正常导航和标签页管理；没有 WhatsApp 翻译/剪贴板等特权 IPC。
5. 会话代理服务：复用现有代理服务，每个持久化账号会话单独绑定，但使用环境级参数。
6. 环境配置应用/检测：配置持久化、支持能力列表、实际值采集和一致性报告。

未来增加平台，仅注册新适配器；不得自动赋予其其他软件的账号数据、预加载或权限。Signal 不注册成空适配器。

## 指纹概览与真实能力

界面可以采用 AdsPower 风格的概览卡片和分组表单，但必须显示“配置值、实际值、支持状态、最后检测时间”，不能把开关存在当作内核能力已实现。

- 代理出口 IP：通过该环境的会话请求检测，不使用宿主默认网络代查。
- 时区：使用检测到的 IANA 时区；自动/手动模式分别保存；IP 变化引起的配置更新需有明确原因记录。
- 语言：HTTP Accept-Language、浏览器语言列表和 Intl locale 一起验证；无法可靠确定的地区提供手动选择，不武断使用“国家=唯一语言”。
- 地理位置：使用 IP 定位的近似坐标及准确度，明确区别于设备真实 GPS；允许关闭/手动设置；不得静默读取设备真实位置。
- UA/UA-CH：优先保持真实内核版本与元数据一致。当前内核不支持的伪装项标记“不支持/只读”。
- 屏幕、硬件、Canvas、WebGL、字体等：区分原生读取与实际可配置能力。没有完成内核实现和验证的项目，不标为已支持。
- 启动不随机重建配置；正常重启应得到同一份配置和相同 revision。发行包升级导致真实内核变化，需要显示版本差异。
- 检测不是封号预测、匿名性或指纹唯一性保证。采集最小必要元数据，不能导出聊天、密码或登录令牌。

若要求与 AdsPower 的定制内核完全等价，需要另立 WhatsApp 专属运行时工作项；不能靠共享 Electron 的全局参数或页面脚本假装完成。

## 实施阶段与验收门槛

### 阶段 0：基线与设计（本次完成）

- 核查当前代码和真实隔离边界。
- 保存 Signal 专属运行文件的 SHA256 基线。
- 运行现有 60 项测试，记录当前状态。
- 本阶段不修改应用运行文件，不提供冒充多标签新版的安装包。

### 阶段 1：环境模型、持久化和无损迁移

- 实现配置仓库和账号会话引用。
- 原账号先一对一迁入环境，原分区完全保留；不先合并 Cookie。
- 仅生成新的配置映射，保留旧配置的回滚路径。
- 验收：重启 ID/配置不变、损坏文件可恢复、未知 schema 拒绝覆盖、路径穿越被拒绝；Signal 保护文件无变化。

### 阶段 2：WhatsApp 与自定义网站多标签页

- 实现两个适配器，以及新增、关闭、刷新、复制、拖动、恢复。
- 现有 WhatsApp 翻译/复制/通知/缩放接入适配器，避免通过重复视图重复累加未读消息。
- 验收：同一账号复制标签可共享该账号登录；同站第二账号不共享；不同源 LocalStorage 不串；不同环境同站 Cookie/缓存隔离；自定义站不能访问宿主特权 IPC。

### 阶段 3：环境概览、联动与检测

- 概览区、配置区、检测区分离；显示真实内核支持能力。
- 代理设置成功后按会话应用语言、时区、近似位置；环境内所有账号会话一致应用。环境更新采用单个串行操作：先暂停相关视图，再应用同一 revision，全部成功后才重新加载；任何必要应用失败时保留可诊断的暂停状态。
- 必要配置应用失败时暂停该环境的外部加载；不得回退为本机直连。
- 相同代理配置不一定意味着轮换代理的每次连接拥有相同出口 IP。检测必须验证各账号会话的实际出口；发现不一致时提示或按严格模式暂停，不能仅凭代理地址相同就显示一致。
- 验收：配置值与各标签页实际值一致；环境间不互相影响；检测失败不显示旧结果为“通过”；不记录敏感数据。

### 阶段 4：Windows 回归、迁移验证和安装包

- 运行完整原有检查及新增环境测试。
- 用多个本地站点、同站不同账号、两个环境和受控代理做真实网络测试，不使用用户提供的真实密码作测试夹具。
- 原有 WhatsApp 功能必须全部回归：扫码界面、输入、复制图片、自动翻译、未读徽标、排序、缩放和代理。
- Signal 必须回归：扫码界面、原生窗口嵌入、账号切换、Ctrl+C/V、Enter、多进程关闭、保存数据和重启。
- 对旧版本数据做迁移/回滚验证，通过后再交付新版。自动化页面测试不能冒充真实手机账号登录验证。

## 本次结果

实现保留旧 WhatsApp 账号入口及其数据，既有账号不被自动迁移。新建浏览器环境可创建新的 WhatsApp 会话和自定义网站会话；它们均使用独立浏览器数据目录。Signal 专属运行文件保持原样。通用网站没有 WhatsApp 特权预加载。
